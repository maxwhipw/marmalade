# 0012. Distil-Whisper distil-small.en bundled as default STT engine

Status: Accepted
Date: 2026-07-23

Supersedes [0005-whisper-tiny-bundled-stt.md](0005-whisper-tiny-bundled-stt.md).

## Context

ADR 0005 bundled **Whisper tiny.en int8** (~117MB) as the default on-device STT,
with Whisper small.en (~374MB) as a downloadable upgrade. Two things changed the
calculus (research 2026-07-22, benchmark notes kept internally):

- **Ethics.** Marmalade's voice stack is R&D toward a privacy-focused STT/TTS
  product built on commercial-clean, documented-provenance weights. Stock
  Whisper (tiny/small) is MIT but trained on ~680k h of undisclosed web-scraped
  audio — ethics "unclear". **distil-whisper** is MIT *and* distilled on
  documented open corpora (People's Speech, Common Voice, GigaSpeech,
  LibriSpeech) — ethics "clear". Nuance: labels are teacher-generated by Whisper
  large-v2/v3, so it's cleaner *provenance*, not a full break from Whisper's
  lineage.
- **A ready drop-in.** The sherpa-onnx maintainer (csukuangfj) publishes
  distil-small.en int8 ONNX in the exact `OfflineRecognizer` layout we already
  use — **~298MB, smaller than the small.en download it obsoletes (374MB) and
  more accurate than the tiny.en it replaces.** No export work.

The server-side STT fallback (`marmaladed` `audio.transcribe`) moved to
faster-whisper + distil-small.en the same week (marmalade repo), so this aligns
the on-device primary path with the server path.

## Decision

Bundle **distil-small.en int8** (sherpa-onnx Whisper `OfflineRecognizer`,
simulated streaming via Silero VAD — the ADR 0005 machinery, unchanged) as the
sole, default on-device STT model. Files in `app/src/main/assets/stt/`:
`distil-small.en-{encoder,decoder}.int8.onnx` + `-tokens.txt`.
`DEFAULT_MODEL_ID = "distil_small_en"`.

- **Remove the Whisper Small download.** distil-small.en is smaller AND more
  accurate, so small.en is strictly dominated; keeping it would advertise a
  worse "upgrade". Orphaned `whisper_small` / `nemotron` download dirs are
  reclaimed on first init; a saved active-model id self-heals to the new default.
- **No on-device upgrade tier ships.** distil-medium.en (~573MB) is server-side
  only — too big for mobile (maintainer, 2026-07-23). The download machinery
  (`ModelDownloadService`, `STTModel.files`) is retained for future tiers.
- **CPU int8 only.** Cross-vendor NPU acceleration for Whisper is a dead end in
  2026 (NNAPI deprecated + crash-prone; Tensor/Exynos/MediaTek closed to
  third-party ONNX Runtime; Qualcomm QNN Snapdragon-only + immature) — see the
  wiki benchmark plan. `provider="cpu"` stays.

## Consequences

- **APK grows ~117MB → ~298MB** (net ~+180MB); 298MB of ONNX enters the git repo
  directly (no LFS, matching the existing tiny.en pattern — a future git-LFS
  migration is worth considering if these assets churn).
- Better contextual accuracy (file names, proper nouns, commands) than tiny;
  cleaner training-data ethics than any stock-Whisper option.
- Model load is a few seconds; `warmup()` on `Dispatchers.IO` at startup still
  applies (ADR 0005 consequence, unchanged). `featureDim` stays 80 —
  distil-small inherits Whisper's 80-mel front-end.
- One on-device model = a simpler Speech Recognition settings screen (no
  download/activate flow surfaces until a future tier is added).

## Rejected alternatives

- **Keep Whisper tiny bundled, offer distil-small.en as a download.** Rejected:
  the clean-ethics + more-accurate model should be the default everyone gets,
  not an opt-in.
- **Moonshine tiny (~125MB, ~48% lower WER than Whisper tiny).** Smaller and
  more accurate, but its training data is undocumented (ethics "unclear" — no
  better than the tiny.en being replaced) and it's a different architecture
  (needs a new loader, not a drop-in). The ethics win is the point here, so
  rejected — noted in the wiki as a future accuracy option if ethics is relaxed.
- **distil-medium.en bundled/downloadable (~573MB).** Too big for mobile;
  server-side only.
- **NPU/GPU acceleration to enable bigger models.** Fragmented/immature
  cross-vendor in 2026; CPU int8 is the portable default.
